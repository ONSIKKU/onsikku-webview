# 온식구 전체 서비스 QA 테스트 계획서

작성일: 2026-04-26  
대상 플랫폼: iOS, Android  
대상 범위: 온식구 모바일 앱 전체 동작, 예외처리, UI/UX, 권한, 데이터 정합성, 회귀 검증  
작성 관점: 30년차 시니어 QA 엔지니어 관점의 실무 실행용 테스트 계획

## 1. QA 요약

- 테스트 대상: 온식구 모바일 앱의 회원가입, 로그인, 가족 생성/참여, 오늘의 질문, 답변 작성, 답변 상세, 댓글/대댓글, 반응, 알림, 히스토리, 마이페이지, 프로필 수정, 초대코드, 차단/신고, 로그아웃/탈퇴, 푸시 알림, 딥링크, 세션 만료 처리
- 핵심 검증 목표: 가족 단위 사용자가 매일 질문을 받고 답변하며 가족 구성원과 상호작용하는 핵심 여정이 iOS/Android에서 끊기지 않는지 확인한다.
- 주요 리스크: 소셜 로그인 리다이렉트 실패, 가족 초대코드 정합성 오류, 질문/답변 상태 불일치, 푸시 토큰 미등록/중복/삭제 문제, 알림 탭 이동 실패, 네트워크 장애 시 빈 화면, 권한 거부 후 복구 불가, 모바일 레이아웃 깨짐
- 테스트 우선순위: P0는 로그인/가입/가족 연결/질문/답변/알림/세션/데이터 저장, P1은 댓글/반응/히스토리/마이페이지/차단/신고, P2는 UI 상태/필터/복사/빈 상태/호환성, P3는 개선성 UX와 문구 품질

## 2. 요구사항 분석

### 명확한 요구사항

- 일반 사용자가 카카오 또는 애플 로그인을 통해 앱에 진입한다.
- 신규 사용자는 약관, AI 동의, 역할, 생년월일/성별, 프로필 이미지, 가족 생성/참여 과정을 완료해야 한다.
- 가족 구성원은 오늘의 질문을 확인하고 본인에게 할당된 질문에 답변할 수 있다.
- 가족 답변 상세에서 답변, 댓글, 대댓글, 반응, 신고, 차단 관련 상호작용을 수행한다.
- 월별 히스토리에서 과거 질문/답변 상태를 확인하고 상세 또는 답변 작성 화면으로 이동한다.
- 알림 목록에서 읽음 처리, 개별 삭제, 전체 삭제, 관련 화면 이동이 가능하다.
- 마이페이지에서 가족 정보, 초대코드, 프로필 수정, 알림 설정, 가족 초대 허용, 로그아웃, 회원 탈퇴가 가능하다.
- iOS/Android 앱에서 푸시 알림 권한과 FCM/APNS 토큰 등록이 정상 동작해야 한다.

### 불명확한 요구사항

- 질문 생성 주기와 발송 시간의 정확한 정책
- 답변 가능 기한, 수정 가능 여부, 삭제 가능 여부
- 가족 최대 인원, 초대코드 만료/재발급 정책
- 댓글/대댓글 최대 길이와 삭제/수정 정책
- 반응 중복 허용 여부와 취소/변경 정책
- 차단 시 상대방 콘텐츠 노출 범위
- 신고 처리 이후 사용자에게 보여줄 상태
- 푸시 알림 유형별 이동 경로와 페이로드 규격
- 회원 탈퇴 후 재가입 가능 시점과 데이터 보존 범위

### 누락 가능성이 있는 요구사항

- 접근성: VoiceOver/TalkBack, 터치 타깃, 색 대비, 동적 글자 크기
- 권한 복구 UX: 알림/사진 권한 거부 후 설정 앱 유도
- 오프라인/느린 네트워크 상태의 재시도 UX
- 서버 401/403/500 응답별 사용자 메시지 정책
- 앱 강제 종료 후 푸시 탭 진입 시 딥링크 복원 정책
- Android 백 버튼과 iOS 스와이프 백 제스처 정책
- 개인정보/민감정보 표시와 로컬 저장소 보안 정책
- 앱 업데이트 후 기존 세션, 푸시 토큰, 알림 설정 유지 정책

### 확인 필요 질문

- 가족 생성/참여 중 중복 가족 가입을 허용하는가?
- 하루 질문은 가족당 1개인가, 구성원당 개별 질문인가?
- 답변 미작성 사용자가 과거 질문에 뒤늦게 답변할 수 있는가?
- 알림 설정 OFF는 서버 알림 설정과 기기 푸시 토큰 삭제를 모두 의미하는가?
- 회원 탈퇴 시 작성 답변/댓글/반응/알림 이력은 삭제 또는 익명화되는가?
- 신고/차단 후 상대방 알림, 댓글, 답변은 어느 범위까지 숨겨야 하는가?
- 앱스토어 심사용 테스트 계정과 테스트 가족 데이터는 누가 관리하는가?

## 5. 예외 케이스 / 엣지 케이스

- 잘못된 입력값: 초대코드 오타, 닉네임 특수문자/이모지, 생년월일 비정상 날짜, URL query ID 변조, 신고 사유 누락, 알림 payload ID 잘못됨
- 빈 값: 닉네임 공백, 답변 공백, 댓글 공백, 가족명 공백, 초대코드 공백, 서버 응답 `null`, 빈 알림 목록, 빈 히스토리
- 최대/최소값: 닉네임 최대 길이, 답변/댓글 최대 길이, 가족 구성원 최대 수, 알림 0건/대량, 월별 질문 대량, 가장 오래된/가장 최신 생년월일
- 권한 없음: 알림 권한 거부, 사진 권한 거부, Apple 로그인 불가 환경, 인증 토큰 없음, 탈퇴/차단된 사용자 접근
- 네트워크 오류: 로그인 중 끊김, 답변 제출 중 타임아웃, 알림 삭제 중 실패, refresh 중 실패, 푸시 토큰 등록 API 실패
- 중복 요청: 답변 제출 연타, 댓글 등록 연타, 반응 연타, 알림 전체 삭제 연타, 초대코드 재발급 연타, 로그아웃/탈퇴 연타
- 새로고침/뒤로가기: 가입 중 뒤로가기, 소셜 로그인 후 앱 복귀 중 중복 딥링크, 답변 제출 직후 뒤로가기, 알림 탭 후 뒤로가기
- 동시성 문제: 두 기기에서 같은 계정 로그인, 가족원이 동시에 답변/댓글 작성, 한 기기 알림 OFF 후 다른 기기 알림 ON, 초대코드 재발급 중 참여
- 데이터 불일치: 홈 응답 상태와 히스토리 상태 불일치, unread 카운트와 알림 목록 불일치, 서버 alarmEnabled와 로컬 alarmEnabled 불일치, 삭제된 알림 딥링크 접근
- 브라우저/기기별 차이: iOS APNS/Android FCM 차이, Android 13+ POST_NOTIFICATIONS, iOS foreground presentation, Safe Area, 키보드 accessory bar, Android 백 버튼

## 9. 커뮤니케이션용 피드백

### PM에게 확인할 내용

- 오늘 질문 생성/발송/답변 가능 기한 정책을 명확히 정의해야 한다.
- 가족 최대 인원, 초대코드 만료, 초대 허용 OFF 동작 정책이 필요하다.
- 차단/신고 후 화면 노출과 알림 발송 범위 정책이 필요하다.
- 알림 타입별 이동 화면과 fallback 화면을 명확히 정해야 한다.
- 탈퇴 후 데이터 삭제/익명화/재가입 정책을 사용자 약관과 맞춰야 한다.

### 개발자에게 확인할 내용

- API별 401/403/404/409/500 응답과 클라이언트 메시지 매핑을 표준화해야 한다.
- 답변/댓글/반응/삭제 계열 API에 중복 요청 방어가 있는지 확인해야 한다.
- 푸시 토큰 등록은 앱 시작, 알림 ON, 토큰 갱신 이벤트에서 모두 upsert되어야 한다.
- 알림 payload의 `questionAssignmentId`, `questionInstanceId`, `link/path` 키 규격을 백엔드와 고정해야 한다.
- 릴리즈 빌드에서 토큰/개인정보 콘솔 로그 제거 또는 마스킹이 필요하다.
- 전체 lint 실패 항목과 generated Android asset lint 제외 정책을 정리해야 한다.

### 디자이너에게 확인할 내용

- 빈 상태, 오류 상태, 권한 거부 상태, 로딩 상태의 화면 문구와 버튼 정책이 필요하다.
- 작은 화면과 큰 글자 크기에서 버튼/카드/하단 탭이 깨지지 않는지 디자인 기준이 필요하다.
- 차단/신고/탈퇴 같은 민감 액션의 확인 모달 문구를 다듬어야 한다.
- 알림 타입별 아이콘과 문구 톤이 가족 서비스에 맞는지 검토해야 한다.
- 다크모드 미지원이라면 라이트모드 고정 정책을 명시해야 한다.

### 운영/CS팀에 공유할 내용

- 푸시가 안 올 때 확인할 순서: OS 알림 권한, 앱 알림 설정, 최신 버전 여부, 재로그인, 기기 재부팅.
- 로그인 실패 문의 시 카카오/애플 계정 상태와 앱 버전, 발생 시간, OS 버전을 수집한다.
- 가족 초대 실패 문의 시 초대코드, 초대 허용 상태, 가족 가입 여부를 확인한다.
- 답변/알림 누락 문의 시 사용자 ID, 가족 ID, 질문 날짜, 알림 타입, 앱 foreground/background 상태를 수집한다.
- 탈퇴/신고/차단 문의는 개인정보와 민감정보 처리 정책에 맞춰 별도 응대 템플릿을 사용한다.
